# Talentwise server models

This package contains the Express API and MongoDB models for the Talentwise recruiting workflow. Each candidate and channel API route reads or writes MongoDB through Mongoose.

## Models

- **RecruitingChannel** — validates channel name and type, monthly spend, active status, and description. Channel names are unique.
- **Candidate** — validates candidate identity, role, recruiting-source reference, pipeline stage, quality score, and application/hire dates. Hires must have a hire date on or after application; other stages cannot have one. `daysToHire` is a virtual value.
- **Candidate resume** — stores private PDF metadata on a candidate; the file itself stays in server-side private storage.

Both schemas use Mongoose timestamps and strict field checking. Candidate stage/date and source/stage indexes support the main pipeline queries.

## Configure and run

1. Copy `.env.example` to `.env` in this directory.
2. Set `MONGODB_URI` to a MongoDB connection string for a database you control.
3. Set `JWT_SECRET` to a random secret of at least 32 bytes. For example, generate one with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` and keep it private.
4. Configure a Google OAuth 2.0 Web application client in Google Cloud Console. Set its client ID as `GOOGLE_CLIENT_ID` in this API environment and as `VITE_GOOGLE_CLIENT_ID` in the client environment. Add the client app origins (for local development, `http://localhost:5173`) to the authorized JavaScript origins. No Google client secret is needed for Google Identity Services ID-token sign-in.
5. To enable AI role-title autocomplete, set `OPENAI_API_KEY` to a private OpenAI API key. `OPENAI_MODEL` is optional and defaults to `gpt-4o-mini`. The API key must only be configured on the server and is never exposed to the client.
6. Optionally set `PORT` (defaults to `5000`) and `CLIENT_ORIGIN` (defaults to allowing browser development origins).
6. Install and start the API:

```powershell
npm install
npm run dev
```

The API refuses to start without `MONGODB_URI`, a valid `JWT_SECRET`, or if MongoDB is unreachable. AI autocomplete is optional; the protected endpoint returns a configuration error until `OPENAI_API_KEY` is set. The React client can access it at `http://localhost:5000/api`.

## Deploy the backend to Render

The repository root contains a Render Blueprint at [`../render.yaml`](../render.yaml). In Render, choose **New → Blueprint**, connect this repository, and select the branch containing `render.yaml` (use `main` after merging this setup, or `feature/render-backend-deployment` before then). Render reads the Blueprint and configures the API service with `server/` as its root, `npm ci` as its build command, `npm start` as its start command, and `/api/health` as its health check.

During Blueprint setup, provide:

- `MONGODB_URI`: a reachable production MongoDB connection string. Restrict its network access to the Render service where supported; never commit this value.
- `CLIENT_ORIGIN`: the exact deployed frontend origin, including `https://` and without a trailing slash. If the frontend is not deployed yet, deploy it first or update this environment variable afterward.
- `GOOGLE_CLIENT_ID`: the Google OAuth Web client ID configured for the frontend's deployed origin. This is a client ID, not a client secret. Update the Google OAuth authorized JavaScript origins to include the deployed frontend origin.
- `JWT_SECRET` is generated by Render for the service and does not need to be provided in a source file.

After deployment, verify `https://<your-service>.onrender.com/api/health` reports `{ "status": "ok", "database": "connected" }`. Set the frontend's `VITE_API_URL` to `https://<your-service>.onrender.com/api` and rebuild/redeploy the frontend.

The Blueprint uses Render's free web-service plan. Its filesystem is ephemeral: candidate resume PDFs saved to local server storage can be lost when the service restarts or redeploys. Do not rely on this deployment for persistent résumé storage or upload sensitive real résumés until you configure durable storage (for example, a paid Render persistent disk or private object storage) and set `RESUME_STORAGE_DIR` or adapt the storage adapter accordingly. A persistent disk is a billable resource; review its current price in Render before attaching one.

## Authentication

Create an account from the React sign-in screen or call `POST /api/auth/register` with `{ "username": "recruiter", "password": "a-strong-password" }`. Usernames are case-insensitive; passwords must contain at least 8 characters and no more than 72 UTF-8 bytes. Passwords are stored as bcrypt hashes. Sign in with `POST /api/auth/login` to receive a one-hour JWT access token.

The client also offers Google sign-in using Google Identity Services. It sends the returned ID token to `POST /api/auth/google`; the API verifies its signature, issuer, expiration, and audience using the configured Google client ID, and requires a verified email before issuing the app's one-hour JWT. Google identities are stored by Google's stable subject ID and are not automatically linked to a password account by email. The client keeps app tokens in memory; signing out or reloading requires signing in again.

Send authenticated API requests with `Authorization: Bearer <accessToken>`. The health check and `/api/auth/register` and `/api/auth/login` are public. `/api/auth/me`, candidate, channel, and analytics endpoints require a valid access token. The JWT secret must remain private and should be different for each environment.

## API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Report API and MongoDB connection status |
| POST | `/api/auth/register` | Create an account and return an access token |
| POST | `/api/auth/login` | Verify credentials and return an access token |
| POST | `/api/auth/google` | Verify a Google ID token and return an access token |
| GET | `/api/auth/me` | Read the authenticated account |
| POST | `/api/ai/autocomplete` | Complete a partial recruiting role title with the configured AI provider |
| GET, POST | `/api/channels` | List channels or create a channel |
| GET, PATCH, PUT, DELETE | `/api/channels/:id` | Read, partially update, replace, or delete/archive a channel |
| GET | `/api/channels/:id/candidates` | List candidates related to a recruiting channel |
| GET, POST | `/api/candidates` | List/filter candidates or create a candidate |
| GET, PATCH, PUT, DELETE | `/api/candidates/:id` | Read, partially update, replace, or delete a candidate |
| POST | `/api/candidates/:id/resume` | Upload or replace a candidate's PDF resume (multipart field `resume`) |
| GET | `/api/candidates/:id/resume` | Download the authenticated candidate's resume |
| DELETE | `/api/candidates/:id/resume` | Remove the candidate's resume |
| POST | `/api/candidates/bulk` | Validate and create up to 100 candidates in one request |
| GET | `/api/analytics/overview` | Read all-time totals, stage counts, and monthly hiring trends |
| GET | `/api/analytics/channels` | Compare applicant volume, hires, hire rate, and candidate quality by channel |

Each candidate stores a required `source` ObjectId reference to a recruiting channel; the channel model exposes the inverse relationship through a Mongoose virtual. `GET /api/channels/:id/candidates` populates that relationship and returns the channel with its related candidate records, using `page` and `limit` pagination. Candidate listing supports `stage`, `source`, `q`, `appliedFrom`, `appliedTo`, `page`, and `limit`. Lists return `{ data, pagination }`. Candidate responses populate the channel source and include resume metadata without exposing the private storage key. PUT replaces all mutable fields; omitted optional fields are cleared and schema defaults are applied. PATCH remains available for partial updates. Candidate PUT requires a valid, existing `source`. A channel that already has candidates is archived rather than removed. Bulk creation accepts `{ "candidates": [...] }`, validates every record and source before writing, and rejects invalid batches without inserting partial data; batches are limited to 100 records. The overview accepts an optional `months` parameter from 1 to 12 (default 6); it includes zero-count months and reports all-time totals separately. Channel analytics includes inactive channels and returns null for quality when a channel has no candidate records.

Resume upload accepts a single PDF up to 5 MB as the multipart `resume` field. The API checks the declared type and file extension, then verifies the file signature before saving. Files are stored outside public/static paths under `server/private_uploads` by default (override with `RESUME_STORAGE_DIR`); keep this directory private and on persistent storage in production. Download and removal require authentication.

## Validate

The test suite uses an ephemeral in-memory MongoDB instance, so no local MongoDB server or credentials are needed to run tests.

```powershell
npm run check
npm test
```
